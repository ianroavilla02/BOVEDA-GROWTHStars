## DT-015 — Vista Detalle Cliente con Soundcharts API

**Prioridad:** Alta
**Categoría:** Producto + Integración externa
**Estado:** Pendiente

### Problema

Hoy la vista Clientes muestra cards básicos con tier/género. Falta vista
detalle interna similar a vista detalle de proyecto, enriquecida con
métricas reales del artista vía Soundcharts API.

### Componentes a implementar

**Header enriquecido:**
- Tier, género, país, status, contact info
- Avatar/imagen del artista (opcional)

**Lista de proyectos del cliente:**
- Mini cards con tipo, fase, fecha
- Click → vista detalle proyecto (reutilizar)

**Métricas Soundcharts:**
- Spotify monthly listeners + tendencia 30d/90d
- Followers por plataforma (Spotify, Apple, IG, TikTok)
- Top tracks con stream counts
- Geographic distribution (top 5 países, top 5 ciudades)
- Demographics (age, gender split)

**Documentos consolidados:**
- File tree reutilizable de vista detalle proyecto
- Agregado todos los entregables del cliente, no solo por proyecto

### Pre-requisitos

- [ ] Cuenta Soundcharts API + API key
- [ ] Decisión arquitectónica: dónde cacheamos data
  - Opción A: `clients.metadata` JSONB en Supabase
  - Opción B: Tabla nueva `soundcharts_snapshots` con TTL
- [ ] Definir frecuencia de refresh (manual / diario / semanal)

### Tiempo estimado

60-90 min implementación + 15-30 min setup API.

## DT-017 — Agente 0 "Baseline Snapshot" / Estado Inicial del Artista

**Prioridad:** Alta
**Categoría:** Arquitectura de agentes + Valor de negocio
**Estado:** Pendiente

### Problema

Hoy el pipeline G*S empieza con `gs-perfilador-artista` (#0). Pero NO
existe captura formal del estado inicial del artista AL INGRESAR a G*S.

Esto impide:
1. Medir ROI real del proceso G*S (sin baseline no hay comparación)
2. Generar prueba social vendible ("subimos al artista X de Y a Z oyentes")
3. Mostrar al cliente avances concretos a mitad de proceso
4. Comparable contra snapshot post-lanzamiento (gs-roi #12)

### Solución propuesta

Crear nuevo agente:

**Slug:** `gs-baseline-snapshot`
**Nombre:** G*S Baseline Snapshot
**Pipeline order:** -1 (antes que gs-perfilador-artista #0)
**Workspace:** growth
**Group:** backend
**Subgroup:** sop
**Rol:** Initial State Recorder / KPI Baseline Capture

### Tracking de métricas

**Audience:**
- Spotify, Apple Music, YouTube, Tidal, Deezer (oyentes mensuales)
- Instagram, TikTok, YouTube, Facebook (followers + reach)

**Engagement:**
- Avg likes per post (último mes)
- Avg views per video (último mes)
- Avg comments per post (último mes)
- Engagement rate (último mes)

**Catalog:**
- # tracks en catálogo
- # releases (singles, EPs, álbumes)
- # colaboraciones featured
- Track más popular

**Geographic:**
- Top 5 países por audiencia
- Top 5 ciudades por audiencia
- % audiencia local vs internacional

**Revenue (si accesible):**
- Streams mensuales totales
- Royalties estimados (calculado o reportado)

### Integración con sistema

- **Output deliverable:** `00-baseline/snapshot-inicial.md` (en cliente folder)
- **Output Supabase:** `runs.output_data` con snapshot JSON
- **Comparable:** gs-roi #12 referencia este snapshot para calcular crecimiento
- **Frecuencia:** una vez al inicio del proyecto, NO se re-ejecuta

### Conexión con DT-015

Comparte fuente Soundcharts API. Mejor implementar juntos para reusar
el cliente API y el código de fetching.

### Valor de negocio

Permite afirmar al cliente con datos concretos:
> "Jot4 R pasó de 12K oyentes mensuales a 87K en 90 días con G*S"

Sin baseline, esto es afirmación. Con baseline, es **dato comprobable**.
